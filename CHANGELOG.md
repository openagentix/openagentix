## [Unreleased]

### Added
- Event callers on the A2A gate (issue #229, ADR 0027, slices 3 and 4, security-relevant). A caller in `governance.a2a.callers[]` may have an optional `event` block (`text`, `rate.perMinute`, `rate.burst`, `maxInFlight`, all required). It is for a system of record that starts one agent run for one of its records: the caller sends `SendMessage` only, as one short text that matches the operator's pattern (a narrow grammar, checked by the chart with `mustRegexMatch` and re-checked by the gate on the `regexp/syntax` tree, which refuses to start on anything else). The gate parses the message strictly (no repeated key, no case variant, only the allowed keys, one text part, no `configuration`, `contextId` or `Content-Encoding`), builds its own body and its own request headers (the caller's bytes are never forwarded), sets `returnImmediately: true`, forwards the message id as `<caller>:<messageId>:<hash of the text>`, answers the sender with the task id and state only, limits the rate (a token bucket per caller) and the open calls per caller (429 with `Retry-After`), and adds `event_id` to the audit line (never the text). ServiceAccount callers only, no `methods`, `memory` or `key`, a fixed user id that no other caller may equal or cover, no agent with long-term memory, no container agent, at most 16 event callers. Off by default: with no `event` block the render is byte-identical to before (checked against the previous chart for ten values sets). The limits are per gate process: N replicas multiply them and a restart refills them. Live proof is the opt-in job `event_triggers` of the `e2e` workflow, and every `e2e` run now also checks that the runtime keeps message ids per user id (`hack/ci/msgid-scope.sh`). After an independent review the gate checks the rate and the open calls before it reads the body (an event caller can never hold more shared slots than its own `maxInFlight`, and a malformed body over the rate gets 429), bounds the JSON-RPC `id` like the message id, drops `Tracestate`, refuses a space under a repeat or an optional in the pattern, answers a runtime error with the fixed status 502, and the chart checks the pattern as strictly as the gate (two shared lists, one of patterns both must accept and one of patterns both must refuse, are read by the chart tests and the gate's Go test), the pattern may have at most 3 spaces and 2 repeated classes with letters, and an event caller may name only agents of `agents[]`. The use cases do not send events yet (slices 5 to 7).

- Diagnostics: the `cluster-read` tool server (issue #230, ADR 0025, slice 3). New Go module `services/diagnostics` with the command `cluster-read`: an MCP server with eight typed, read-only tools (`pods_list_in_namespace`, `pods_get`, `pods_log`, `events_list`, `workloads_list`, `workloads_get`, `nodes_list`, `nodes_get`) over the cluster it runs on, in namespaces given by two flag lists (log namespaces and status-only namespaces). Results are built from a field allowlist (no environment values, probe headers, exec commands, annotation values, CSI attributes or `managedFields`), every kept string is stripped of control characters, redacted and cut, free text sits in `untrusted_text` fields, logs are capped (200 lines, 64 KiB, 3600 seconds, 2048 bytes a line), status-only namespaces get no logs, no terminated messages and no probe or hook output, and there is one audit line per call with no content. At start and every 5 minutes the server checks its own rights (`SelfSubjectAccessReview` for every forbidden right ADR 0025 lists, in each listed namespace, in `kube-system`, in `openagentix-diagnostics` and at cluster scope) and serves nothing while one is allowed. ### Changed
- A misspelt key in a `governance.a2a.callers[]` entry (for example `userid:` or `agent:`) now fails the render with the caller name and the key. Before, the chart read only the keys it knew and dropped the rest without a word, so the caller got the defaults. The allowed keys are `name`, `serviceAccount`, `agents`, `userId`, `methods`, `memory` and `event`. Every values file in this repository and every form the chart comments describe renders as before (ADR 0027).
- Tool profiles: the tool server of every profile now allows only tool calls and tool listing (issue #229, follow-up of ADR 0026 slice 2). The aggregation filter of a profile covers tools only, and the policy of a profile server used to permit every action, so a profile server could also list and read resources and prompts of the other backends of its group. Now each profile server (the ones for chart agents, the ones with a `-workload` variant for container agents, and the diagnostics profiles) has an allow list as its policy: `call_tool` on each of the profile's tools (and `execute_tool_script` with code mode) and `list_tools`, nothing else, so every other method is denied by default. A workload variant keeps its condition on pod-bound tokens of the workload namespace on every permit. The shared tool server `tools` is unchanged. Upgrade note: the `VirtualMCPServer` objects of the profiles change (their `authzConfig.inline.policies`), so the quick start and the full demo render differently and ToolHive restarts the profile servers on upgrade; a profile whose agents use only tools is not affected. A client that read a resource or a prompt through a profile server now gets a refusal: list the tool you need in the profile instead.
- Admission guard and control plane: the short form `<service>.<namespace>` of a cluster name is now treated as a cluster name (issue #229, ADR 0026, slice 2). The host rule of the `EgressPolicy` guard and `catalog.InternalEgressHost` in the controller treat a host whose last label has not the shape of a public top level domain (two to 63 letters, or a punycode label), such as `records.fernvale-records` or `records.team1`, like the `.svc` forms: refused unless the operator lists exactly that host and port. A namespace of letters only (`payments`) has the shape of a top level domain, and nothing offline can tell the two apart; for an endpoint of `mcp.endpoints` the catalog carries the endpoint's namespace (`namespaces.endpoints`), and the guard and the controller refuse a host in it in every form, and the chart refuses it at render. Upgrade note: with the control plane on, the guard object `openagentix-control-plane-guard-egresspolicies` changes (one CEL line and two comment lines), and a definition whose egress origin is such a short name is now refused.
- Runtime bring-up: hardening. `components/runtime/up.sh` no longer puts the database passwords of kagent's PostgreSQL in a process argument. The secrets are made with `--from-file` from a process substitution, as `install.sh` does, and the two role passwords reach `psql` as `\set` lines on standard input. The code moved to `components/runtime/kagent-db.sh`. Tested with a fake `kubectl` that records every argument and all standard input (`components/runtime/tests/run.sh`, shown failing first). Not run on a cluster.
- Telegram bridge: hardening. Replies are sent with link previews turned off, as the notify service already does, so a reply no longer causes Telegram to fetch a link in it. Tested on the request body (`TestSendMessage_LinkPreviewsOff`, shown failing first).
- CI: the `e2e-k3s` job shows its real result (issue #195). `continue-on-error: true` is removed, so a failed install, smoke test or NetworkPolicy test on k3s is a red check instead of a green one. It is still not in `ci-ok` and not a required check of `main`, so it does not block a merge. Before this, 13 of 23 completed runs had failed while showing green.
- Chart: the model gateway Service is now `ClusterIP` by default (`gateway.serviceType`, ADR 0023). Upgrade note: on upgrade its load balancer is removed. If you reach the model gateway from outside the cluster through it, set `gateway.serviceType: LoadBalancer` before you upgrade, or use `kubectl port-forward`. The default chart render has two more things than in 0.2.0: an `AgentgatewayParameters` object and `spec.infrastructure.parametersRef` on the Gateway.
- `uninstall.sh` names the kube context on every `kubectl` and `helm` call and removes nothing unless that context exists, is the current one after the switch and, with `CLUSTER_TYPE=remote`, its API server answers (issue #169). An unknown `CLUSTER_TYPE` is now refused. It also deletes the namespace `openagentix-node-settings` when present. It never deletes a cluster; on remote it prints the cloud teardown reminder (load balancers and disks first, then the cluster). kind and k3d use the same context as before.
- Container agents, A2A gate: a container agent has 300 s to start its answer, streaming calls included (the body is not timed); `controlPlane.containerAgents.responseTimeoutSeconds` changes it. Each container agent handles 32 calls at once (`maxInFlightPerAgent`), and all container agents together share half of the gate's slots, so the built-in agents keep theirs. The cost: 32 slow calls make one agent answer 503 for every caller until they end. Only `Content-Type`, `Accept`, `A2A-Version`, `A2A-Extensions`, `Traceparent` and `Tracestate` from the caller (plus the gate's own `X-User-Id`) reach a container agent. Only `Content-Type`, `Content-Length`, `Cache-Control`, `Date` and `X-Accel-Buffering` come back from it, plus `X-Content-Type-Options: nosniff`; a redirect from it becomes a 502.
- Container agents: the image is pulled again on every start (`imagePullPolicy: Always`). The chart value `controlPlane.containerAgents.imagePullPolicy` sets it; the quick start uses `IfNotPresent` because its image exists only on the node. Container agents that already run restart once on upgrade, and while the registry is down a restarted agent cannot start.
- Admission guard for container agents: more fields are pinned to what the adapter writes (pull policy, scheduler, termination settings, rollout strategy, probe scheme and timeout, Service cluster IP, session affinity and traffic policy).
- `hack/kind-image-digest.sh` takes the tag that was just loaded as a third argument and uses its digest; on a reused cluster it no longer picks an older image of the same repository.
- Docs: ADR 0015, the README and `what-works.md` now say that DNS lookups can leave the cluster by default, that NetworkPolicy isolation needs a cluster that enforces it, and that the model in a container agent's definition is a hint.

### Fixed
- kagent-controller no longer crash-loops after a node restart (issue #178). Root cause: kagent 1.0.1 dials the Substrate API once at start-up with a fixed 10 s deadline (`substrate.Dial`; not configurable) and exits when the API does not answer. After a node restart the Substrate API is often not serving for one to three minutes, because its pod waits for a pod certificate and for the Substrate PostgreSQL. The kagent chart has no value for init containers, so `components/runtime/kagent-helm.sh` now passes a helm post-renderer (`components/runtime/kagent-postrender.sh`, uses `kubectl kustomize`) that adds the init container `wait-for-ate-api` to the `kagent-controller` Deployment: it waits until `api.ate-system.svc:443` accepts a TCP connection (up to 660 s, then it exits 1), with the image the install already pulls for the Substrate PostgreSQL, non-root and read-only. Nothing else in the render changes. In 6 `recovery` runs on the branch the controller restarted 0 extra times (before: extra restarts in 3 of 6 runs). A cluster installed earlier gets the change on the next `kagent-helm.sh` run.

### Fixed
- Agent Kourier lost its API server access, and crash-looped until the installer was run again, when the kind node's address changed after a Docker restart (`172.18.0.2` to `172.18.0.3`): its NetworkPolicy allowed the address found at install time as a `/32`. `components/channels/kourier.sh` now allows, on kind (every node's `spec.providerID` starts with `kind://`), the `/24` of the API server's node address, and keeps the exact endpoint addresses (`/32`) on every other cluster. `KOURIER_APISERVER_CIDRS` (comma or space separated CIDRs) overrides the detection. The next `./install.sh` run migrates an existing release. The derivation is in `components/channels/apiserver-cidrs.sh`; not yet run through a real Docker restart.
- Telegram bridge: privacy fix for long-term memory.
