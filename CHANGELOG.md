# Changelog

All notable changes to OpenAgentix are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

No default changed for users who leave the new `controlPlane` and `console` blocks off. The default chart render is the same as in 0.2.0.

### Fixed
- Docs: the console and A2A gate READMEs, the console feature page, the A2A gate reference and a few chart comments now match the code (console headers, NetworkPolicy egress and chart env; gate health routes, log level, refusal reasons and the container agent settings; `allowKnowledge` and `allowNotify` comments name `spec.knowledge.enabled` and `spec.notify.enabled`).
- Installer, quick start: `hack/kind-image-digest.sh` adds a `name@sha256` name on the kind node for an image loaded with `kind load` (kind keeps only the tag with the containerd image store); the wait for the AgentDefinition quota status is now up to about two minutes and nudges the quota controller; `hack/ask.sh` reads a direct `{message}` result as well as `{task}`. The sample `echo-a2a` now answers with `{message: ...}` as A2A 1.0 requires.
- Console traces: the recent-turns list used Jaeger's v1 search (`/api/traces`), which Jaeger v2 does not serve, so `GET /api/v1/traces` always answered "not available" against the bundled Jaeger. It now searches with `/api/v3/traces` (OTLP JSON) and treats Jaeger's 404 "No traces found" as an empty list.
- Installer: every image it builds is now tagged `dev-<hash of its source>` and the tag is passed to the chart (`hack/image-tag.sh`). Before, all images used the tag `dev`; `kind load` keeps an existing tag on the node and the pods use `IfNotPresent`, so a rebuilt image never replaced the one running. A changed source now always gives a new image reference. Affects the bridge, a2a-call, kb, notify, a2a-gate, stub-model, control plane and console images. `SKIP_*_IMAGE` still leaves the chart's `dev` tag.

### Added
- Installer: `CLUSTER_TYPE=k3d` creates and uses a k3s cluster in Docker (k3d) instead of kind (issue #30). One helper, `hack/cluster.sh`, holds what differs (context, node name, image load with `k3d image import`, cluster creation without Traefik and ServiceLB, containerd socket); `install.sh`, `components/runtime/up.sh`, `hack/kind-image-digest.sh` and `uninstall.sh` use it. The default stays kind and its commands do not change (`hack/ci/cluster-test.sh` checks both). New non-blocking CI job `e2e-k3s`: on a hosted runner, k3s v1.37.2 in Docker passed the quick start with the sample container agent (28 smoke checks, 5 min 51 s) and `hack/ci/netpol-test.sh` showed NetworkPolicy enforced for ingress and for egress to the internet. k3d gets a Docker volume at `/var/lib/ate`, without which the runtime cannot build sandbox roots (`mknod` is refused on a container's overlay root). Guide: `docs/diary/guide/install-k3s.md`.
- Bring your own agent, slice 1 (ADR 0015, issue #43), off by default (`controlPlane.containerAgents.enabled`, policy `allowedRuntimes` default `[builtin]`). `AgentDefinition.spec.runtime` with `type: container` runs a digest-pinned A2A image as a hardened Deployment in the namespace `openagentix-workloads` (Pod Security `restricted`, deny-by-default network rules), with its own gateway key, a Service, ServiceAccount and NetworkPolicy. New admission guard policies are key allowlists. The A2A gate routes listed agents to the workload namespace from a controller-written route list (no URL in it) and rewrites their agent card. New `status.capabilities.isolation`. Instructions, tools, tool profile, egress, memory, knowledge, notify and skills are refused for container agents. Sample: `examples/agents/echo-a2a`; `QUICKSTART_BYO=1 PROFILE=quickstart ./install.sh` runs it on the quick start and the `e2e` job checks it (Ready, answer through the gate from the stub model, gateway user, three refused definitions). The console registry shows runtime type and isolation, read only; container agents are created with kubectl (#107). The default render does not change.
- API reference on the docs site (`docs/diary/reference/`): `AgentDefinition`, platform policy and catalog, console HTTP API with an OpenAPI 3.1 file, A2A gate, admission guard, reserved kinds, API conventions. Field tables, condition reasons, violation sentences and policy defaults are generated by `hack/docs/gen-reference.sh`; `hack/docs/tests/run.sh` (in `make test-shell` and CI) fails when a page, an example or the OpenAPI route list drifts from the code.
- Quick start profile (ADR 0014): `PROFILE=quickstart ./install.sh` installs one governed agent with no model key and no chat token. The installer picks the model (a key or OpenAI-compatible endpoint in the environment, a local Ollama on request, else a scripted stub model, `services/stub-model`). `hack/ask.sh` asks an agent through the A2A gate. The keyless e2e job (`.github/workflows/e2e.yml`) runs it on a hosted runner with `hack/ci/smoke.sh`.
- Control plane (ADR 0007 slice 1, ADR 0012 contract), off by default (`controlPlane.enabled`). A new resource kind `AgentDefinition` (`openagentix.io/v1alpha1`, short name `oad`) and a controller in `services/control-plane` (Go, standard library only; a core plus adapters for the kagent runtime, the agentgateway keys and the ToolHive tool profiles). A definition becomes a runtime agent, a gateway key and a status with conditions, an endpoint and a revision. Platform catalog and policy ConfigMaps decide what a definition may use. Demo values: `components/control-plane/demo-values.yaml`, example `components/control-plane/researcher.yaml`.
- Suspend and resume: `spec.suspend` stops the agent, removes the runtime agent and the gateway key entry, and sets `Ready=False` with reason `Suspended`. Resume restores the same key.
- Web console (ADR 0007 slice 3), off by default (`console.enabled`): `services/console` (Go API with fixed routes, bearer token, Content-Security-Policy, Host allowlist, login throttling, extension points for authentication, authorization and audit) and `console/` (SvelteKit single-page app: shell, agents registry, agent builder with options that follow the policy, YAML view, pause, delete). Other areas show "not available yet". Design contract `docs/console/UI-SPEC.md`, approved mockup `docs/console/mockup.html`. Demo values: `components/console/demo-values.yaml`. The installer creates the token Secret `console-token`. There is no ingress: use `kubectl port-forward`.
- API conventions for all resource kinds (`docs/api-conventions.md`).
- Decision records: ADR 0007 (control plane and console), 0008 (model routing), 0009 (FinOps and tracing direction), 0010 (project structure), 0011 (foundation readiness), 0012 (platform primitives for products built on top), 0013 (one focus, bring your own agent, adopted identity, postponed work).
- Project process: governance and community files, DCO sign-off on commits, issue templates, a decision process, and a roadmap with milestones 0.3 to 0.6 and a Backlog (68 issues).
- CI on every push: Go per module, chart tests, shell tests, integration, the admission guard, an API-server test, console unit and end-to-end tests, image builds and a secret scan (`hack/ci/README.md`).
- The install command now takes ten demo values files. The two new ones, `components/control-plane/demo-values.yaml` and `components/console/demo-values.yaml`, go last, in that order.

- Console: Overview, Models, Tools, Skills, Memory and Governance show real, read-only data from `GET /api/v1/platform` and `GET /api/v1/agents` (agents by state, what needs attention, active adapters, which agents use each model, profile and skill, the platform policy as a summary and as YAML, effective egress and tools per agent). The agents list now carries `effectiveTools` and `effectiveEgress`, and the platform policy carries `suspendAll`. Spend, traces, counts from jobs and gate caller rules stay "not available" because the console has no source for them.

- Console metrics: `GET /api/v1/metrics/summary` reads spend, tokens, requests, cache-read share, spend per gateway user and a 24-point series from a Prometheus-compatible store (`CONSOLE_METRICS_URL`; the bundled VictoriaMetrics when observability and the bundled profile are on, or `console.metrics.url`). The queries are fixed text in `services/console/internal/observe`, behind a small `Observability` interface (ADR 0009); the browser chooses only `24h` or `7d`. The Overview shows spend tiles with a sparkline and spend per agent, and the Costs page shows the same data with a window selector. Only the console may reach the bundled store's query port (NetworkPolicy).

- Console traces: `GET /api/v1/traces` (recent agent turns) and `GET /api/v1/traces/{traceId}` (the spans of one turn) read the bundled Jaeger query API (`CONSOLE_TRACES_URL`). Fixed server-built queries, a hex-validated trace id, bounded look-back and limits, and an allowlist of span attributes so prompts, answers and tool arguments are never passed on. The Traces page shows recent turns and a waterfall with a span detail panel. Metrics and traces sit behind one `Observability` interface; only the console may reach Jaeger's query port (NetworkPolicy).

### Changed
- Documentation: the README and the docs site landing page start with a short definition, what you get, a diagram of the request path, the quick start and the status; the detailed reference follows below. New pages: Why OpenAgentix, Concepts, Use cases and FAQ (`docs/diary/guide/`). `what-works.md` now lists the quick start and the keyless e2e job. The README notes that the in-cluster `curl` check of the full demo is, by reading the chart, not an admitted caller under the controller's NetworkPolicy (not re-run).
- Console sidebar: the lock now means "read-only in this release" (pages that show data); a dotted circle means "no data source yet".
- The `AgentDefinition` contract follows ADR 0012: `spec.knowledge` and `spec.notify` are objects (`enabled` plus a reserved list), `spec.skills` is a list of `{name, version}`, the gateway user of a built agent is `<namespace>.<name>` (for example `kagent.researcher`), and the status has public fields (`conditions`, `endpoint`, `revision`, `effectiveTools`, `effectiveEgress`) and a private `status.controller` part.
- The control plane's admission guard is an allowlist: 8 ValidatingAdmissionPolicies that allow only the fields the controller writes.

### Fixed
- Console: the context line under the logo was clipped when the sidebar was taller than the window. It no longer shrinks, and shows the namespace when no context name is set.
- The API server refuses a CRD schema that describes `metadata`. The schema no longer does, and an API-server test covers it. This was found only by a live upgrade.
- Two independent reviews found problems, all fixed test-first. First review: no critical, 7 important, 12 minor. Second review, after the console: 1 critical, 6 important, 17 minor.
- The console embed placeholder is now committed, so a clean checkout builds.

### Security
- The controller never reads a Secret and has namespaced Roles only. The console's ServiceAccount cannot read Secrets and cannot write kagent resources.
- Critical finding of the second review: the guard checked egress hosts but not the field of an egress policy that injects a Secret into outbound requests. The guard was rewritten as an allowlist. It is now run in CI with the Kubernetes admission code (406 cases) and against a real API server (71 checks).
- Suspend cuts the agent's access to the model, not only its runtime agent.
- A `ResourceQuota` limits the number of definition objects (`controlPlane.maxDefinitions`).
- Console review findings fixed: strict token length, Host allowlist against DNS rebinding, errors from the cluster are never sent to the browser.

### Known limits
- Proven on one single-node kind cluster and one namespace only.
- Chart agents (`agents[]`) are not migrated to definitions and are read-only in the console.
- Schedules, Kourier bindings and the Telegram bridge cannot point at built agents yet.
- Nobody can call a built agent through the A2A gate until an operator adds a caller rule.
- Suspend is a stop, not a pause.
- Memory for built agents needs a chart agent with memory, so that the memory stack is installed.
- Bring your own agent is planned for 0.3, not built.
- The end-to-end install in CI runs the quick start profile only (kind on a hosted runner), and is not yet a required check.
- The browser UI was not driven against the real cluster in the live run, only through the API. The Playground does not exist yet.

## [0.2.0] - 2026-11-25

Everything built after the MVP: knowledge base and knowledge graph, long-term memory, channels and triggers, schedules, notifications, observability, tool-layer identity, and the governance rounds of ADR 0006 (A2A gate, tool profiles and per-agent egress, memory governance). Runs on one kind node; read `docs/diary/what-works.md` before relying on anything.

### Upgrade notes
- The kagent UI is closed to every pod by default (`networkPolicy.kagentUI.allowFrom` for exceptions); open it with `kubectl port-forward -n kagent svc/kagent-ui 8080:8080`.
- The vMCP refuses anonymous callers by default (`mcp.virtual.incomingAuth.type=anonymous` restores the old behaviour).
- Prompt caching is on by default (`gateway.policy.promptCaching.enabled=false` turns it off).
- The knowledge base is deployed by default (`knowledge.enabled=false` to leave it out).
- The bring-up scripts moved from `spikes/kagent/` to `components/runtime/`.
- With the knowledge graph on, migration 0005 clears extracted graph rows once; re-ingest the collections to rebuild the graph.
- Governance (A2A gate, tool profiles, egress allowlists, memory expiry and memory commands), the knowledge graph, channels, schedules, notifications and observability are all off by default.

### Security
- Memory governance hardening after review: the expiry job keeps the database password out of the process arguments (`PGPASSWORD`); the bridge refuses `/forget` outside a private chat, ignores forwarded memory commands, and bounds the `/memories` reply in UTF-16 code units.
- **Default changed:** the kagent UI is closed to every pod. A new NetworkPolicy `openagentix-kagent-ui` (rendered whenever `networkPolicy.enabled` is true, which is the default) selects the UI pods and admits nobody; `networkPolicy.kagentUI.allowFrom` lists peers. The UI proxies the controller's whole API (memory, sessions, A2A over gRPC-Web) and forwards `X-User-Id`, so an open UI was a relay around the A2A gate, with the gate on or off (a pod in `default` got HTTP 200 on the memory List call). Open the UI with `kubectl port-forward -n kagent svc/kagent-ui 8080:8080`; this still works under kindnet. Default and demo renders are no longer byte-identical to before for this reason.
- Port 8083 admits the kagent UI pods (by label) instead of the whole `kagent` namespace; the tools server and the worker pool do not call the controller, and the sandboxes arrive through `atenet-egress`.
- A2A gate: a per-caller JSON-RPC method list (`methods` in the rule; the chart sets what its own callers send, the default is `SendMessage` and `SendStreamingMessage`; `governance.a2a.callers[].methods` for extra callers). A method outside the list, or a JSON-RPC body whose method cannot be determined within `A2A_GATE_SNIFF_BYTES`, gets 403 with `reason: method` (fails closed). The audit line has a new field `rpc`.
- A2A gate limits: 16 KiB request headers, a 10 s read deadline for the start of a body (cleared before proxying), at most `A2A_GATE_MAX_INFLIGHT` (default 128, chart `governance.a2a.maxInFlight`) requests at once (503 when full), the sniff buffer sized by `Content-Length`; bearer values over 8 KiB refused, a pre-check of the token payload (audience, issuer, expiry) before a TokenReview, one review per token at a time, at most 8 at once, and separate bounded caches for good and bad tokens.
- A2A gate: the claimed `X-User-Id` is recorded in the audit line only after authentication and cut to 128 bytes.
- Documentation: a ServiceAccount per schedule does not stop someone who can create pods in `openagentix-schedules` from acting as any schedule; the boundary is RBAC for creating pods there. ADR 0006, the security and schedules diary pages and the README now say so. A ValidatingAdmissionPolicy is a possible later step and is not built.

### Added
- Memory governance, round 3 of [ADR 0006](docs/decisions/0006-governance.md) (**off by default**: with `memory.expiry.enabled`, `bridge.memoryCommands` and `memory: true` unset, 26 default, demo and option renders are byte-identical to before):
  - `memory.expiry`: a CronJob `memory-expiry` in the `kagent` namespace that runs kagent's own two prune statements (`PruneExpiredMemories`, `go/core/internal/database/memory.go` lines 125-139; nothing in kagent calls it and its search ignores `expires_at`, so memories never expired). Expired rows read at least ten times get fifteen more days, the other expired rows are deleted. psql from the image of kagent's own database (`pgvector/pgvector:pg17`, by digest), the existing Secret `kagent-postgres-readwrite` by reference, a non-root read-only pod, counts only in the log. A NetworkPolicy `openagentix-kagent-pg` then admits only the controller and the job to kagent's PostgreSQL (open to every pod before). Search and list still return expired rows until the job has run.
  - `memory.expiry.secretScan` (report only) and `secretScanDelete`: per pattern name, the count of memory rows that match ten well-known secret shapes (key headers, AWS, GitHub, Slack, Google, Stripe, Telegram, provider keys, bearer tokens, JWTs). Never the text.
  - A2A gate: a caller whose rule has `memory: true` may call `MemoryService` `List` and `Delete` over binary gRPC-Web, only for the agents and user ids of its rule; everything else of gRPC stays 403. The user is `X-User-Id` (set by the gate from the rule), not the message; the gate parses the one frame and refuses anything but one allowed `agent_name`, within 600 bytes, and forwards the bytes it verified. Audit `rpc` field, no content. `governance.a2a.callers[].memory`.
  - Telegram bridge: `/memories` (at most 10 items of 200 characters) and `/forget`, then `/forget confirm`, for the chat's own user id, through the gate (`bridge.memoryCommands`, `MEMORY_GATE_URL`, `MEMORY_AGENT`). A confirmation step, a bounded reply, generic errors, no content or chat id in the log.
  - `components/governance/memory-demo-values.yaml`; `charts/openagentix/tests/memory-expiry-integration.sh` (29 assertions against a throw-away PostgreSQL that the script starts and stops); 74 new chart assertions (901 in all); 11 new gate tests (62) and about 25 new bridge tests (122).
  - Proven on kind with two model calls (one turn): the expiry job completed with counts only and the nine existing rows were untouched; `List` and `Delete` for an own `probe:` id worked, another user id, another agent, a second message field, other RPCs and a caller without the flag were refused; a real saved memory was listed and deleted through the gate. Not run: a real Telegram `/memories` or `/forget`, a deletion of an expired row on the cluster.
- Finding: kagent's database logins are `NOINHERIT` (kagent runs `set_config('role', ...)` after each connect), so the expiry job runs `SET ROLE kagent_readwrite`.
- Tool profiles and per-agent egress, round 2 of [ADR 0006](docs/decisions/0006-governance.md) (**off by default**: with no `mcp.profiles`, no `toolProfile` and no `egress`, 28 default, demo and option renders are byte-identical to before):
  - `mcp.profiles`: each profile renders a VirtualMCPServer `<virtual.name>-<profile>` on the same MCPGroup with `defaultToolVisibility: deny` and per-backend tool filters (MCPServer and MCPServerEntry backends alike), its own OIDC audience `<oidc.audience>-<profile>` on the shared MCPOIDCConfig, an optional `codeMode`, a RemoteMCPServer `<remoteMCPServer.name>-<profile>` with the matching `actorJwt.audiences`, and ingress and metrics NetworkPolicies equal to the shared vMCP's. The kb and notify policies admit every profile vMCP.
  - `agents[].toolProfile`: the agent's tools come only from the profile's RemoteMCPServer. The render fails for an unknown profile, a tool that is not in the profile, `execute_tool_script` on a profile without `codeMode`, a tool entry that names another server, duplicate or invalid profile names, an unknown backend, an empty tool list, and a profile with `incomingAuth.type` other than `oidc`.
  - `agents[].egress.allow`: renders an `EgressPolicy` `<agent>-egress` and `egressPolicyRefs`. The render fails for a malformed origin (kagent's own pattern), a duplicate, more than 64 entries and an origin inside the tools namespace.
  - `components/governance/profiles-demo-values.yaml`: one profile `lookup` and a small agent `profile-demo` on it with one `egress.allow` origin; `assistant` stays on the shared vMCP. `install.sh` waits for each profile vMCP to be Ready.
  - 103 new chart assertions (827 in all). Proven on kind with two model calls: a profile agent answered with an allowed tool through the A2A gate and `assistant` still completed; refusals (hidden tools directly and in code mode, the shared vMCP, `fetch` proxy and kb, hosts outside `egress.allow`) ran through the real sandbox with a stub model. One extra vMCP pod measured at about 30 MB and a few millicores idle.
- Finding recorded in ADR 0006: the Substrate egress proxy replaces an `Authorization` header that the request already carries; it does not add one. Without a header a vMCP answers 401.
- A2A gate, round 1 of [ADR 0006](docs/decisions/0006-governance.md) (**off by default**: with `governance.a2a.enabled: false` every default and demo render is byte-identical to before): `services/a2a-gate`, a small Go reverse proxy (standard library only) in front of the kagent controller's port 8083. It authenticates the caller (a projected ServiceAccount token checked by TokenReview with the audience `openagentix-a2a` and a 30 s cache, or a static key matched by SHA-256), applies the caller's rule (allowed agents, user id `exact`, `prefix` or `fixed`), passes only `POST /agents/<ns>/<name>` and the agent card, answers 403 for gRPC, gRPC-Web and everything else, removes `Authorization` and the `user_id` query, sets `X-User-Id` itself, passes SSE with an immediate flush, and writes one JSON audit line per request (user id hashed by default, `contextId`, trace id, status, duration, never message text).

With the gate on: port 8083 admits only the gate, `atenet-egress` and the `kagent` namespace; the bridge and every schedule get a projected token (one ServiceAccount per schedule) and call the gate; Kourier bindings get `identity.tokenSecretRef` and the AgentBackend points at the gate; the render fails for `networkPolicy.extraA2ACallers` without a matching caller rule. 78 new chart assertions.

- Curated knowledge-graph facts, no model involved ([ADR 0004](docs/decisions/0004-knowledge-graph.md), "Curated facts"; only with the graph on, routes absent otherwise): a **fact set** is a named, hand-written catalogue of entities and relations of one collection. kb admin routes `PUT/GET/DELETE /v1/collections/{collection}/graph/factsets/{id}` and `GET /v1/collections/{collection}/graph/factsets` (same admin token, body limit and no-content logging as the document routes): `PUT` replaces the fact set atomically and idempotently (the same body twice changes nothing and answers `changed: false`; facts that left the body are removed), at most 2000 entities and 5000 relations (413), every other mistake a 400 naming the item (`relations[7]: target is not an entity declared in this fact set`). Entity types, name length and predicate form as in extraction, but no grounding or generic-name rule; both ends of a relation must be declared in the same fact set. Stored with `origin = 'manual'`; a curated entity merges with an extracted one by canonical name and its name, type and description win; deleting or re-ingesting documents never removes it, deleting a fact set only un-marks entities that extracted facts still use. Migration 0006 (relations cite a document chunk or a fact set; tables `graph_factsets`, `graph_factset_entities`; existing rows kept; tested as an upgrade from the schema of migration 5).
